# hack-9923a583-ctrl-c
Hackathon team repository for ctrl+C

## Backend: каталог подрядчиков

Первый этап бэкенда использует SQLite. Схема хранит профили в `vendors`, а списки категорий, форматов, языков и занятых дат — в JSON-столбцах.

Когда Python 3.10+ установлен, из корня проекта создайте и заполните локальную базу:

```powershell
python backend/import_dataset.py
```

По умолчанию скрипт читает `hackathon dataset anonymized .csv` в корне проекта и создаёт `backend/data/vendors.sqlite3`. Повторный импорт обновляет профили с теми же ID. Путь к CSV или базе можно переопределить флагами `--csv` и `--db`.

### API подбора

Установите зависимости и запустите сервер из корня проекта:

```powershell
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.main:app --reload
```

Фронтенд отправляет `POST http://localhost:8000/api/recommend` (также доступен `/api/recommendations`):

```json
{
  "city": "Алматы",
  "date": "2026-11-14",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget": 1000000,
  "duration": 5,
  "language": "русский"
}
```

В `backend/matching.py` город, категория, незанятая дата и формат — обязательные условия: каждое даёт 1 балл при совпадении, а несовпадение исключает профиль. Бюджет даёт 10 баллов, если цена не выше бюджета; цена ниже бюджета дополнительных преимуществ не даёт. Превышение бюджета до 30% допускается со снижением на 1 балл за каждые начатые 3%: при превышении ровно на 30% за бюджет остаётся 0 баллов. Превышение более чем на 30% исключает профиль. Длительность даёт до 10 баллов: если лимит меньше запроса, отнимается 2.5 балла за каждый недостающий час; выбранный язык даёт +3 за совпадение и −1 за несовпадение. Максимум — 27 баллов при заданных длительности и языке или 14 баллов без обоих необязательных параметров. Порог выдачи — 25% максимума по запросу с округлением вниз: 6 баллов из 27 или 3 из 14. Сортировка — по сумме баллов, затем по ID; наружу выдаются максимум три карточки. В карточке видны общий балл и блок «Почему рекомендуем» с объяснением начисленных баллов. `backend/recommender.py` формирует статусы и объяснения пустых результатов. Ответ соответствует фронтенду: `status` (`success`, `category_not_found` или `no_matches`) и карточки в `results`. `GET /api/health` — проверка доступности сервера.

Фронтенд и API принимают даты с 23.09.2026 по 31.12.2026 включительно. Бюджет должен быть положительным целым числом, формат — одним из шести форматов каталога; длительность, если задана, — положительным конечным числом. Некорректные параметры возвращают HTTP 422. В карточке явно показан источник: «Из исходного датасета» или «Синтетический профиль».

При запуске API проверяет наличие таблицы и профилей. `GET /api/health` возвращает HTTP 200 и число профилей (`profiles`), только если каталог готов. Если база отсутствует, пуста или имеет неподходящую схему, health и подбор возвращают HTTP 503 с подсказкой выполнить импорт. После импорта перезапуск не нужен. Чтение не создаёт пустую базу, соединения SQLite закрываются явно.

Фронтенд ожидает ответ не дольше 10 секунд и проверяет его структуру. Ошибки сервиса показываются отдельно от пустой выдачи; технические детали остаются в консоли браузера. Объяснение и зелёные теги совпадений видны сразу, полное описание раскрывается по нажатию.

### Сценарии для демо

1. **Плотная категория с ранжированием:** Алматы, 13.10.2026, корпоратив, Ведущий, бюджет 800 000 ₸, 8 часов, русский язык. В текущей базе топ-3 набирает разные баллы.
2. **Редкая категория:** Алматы, 23.09.2026, свадьба, Флорист, бюджет 2 000 000 ₸, без языка и длительности. Доступны два профиля.
3. **Пустой результат:** Алматы, 26.09.2026, свадьба, Флорист, бюджет 20 000 ₸. Один кандидат занят, второй превышает бюджет более чем на 30%.

Чтобы показать влияние календаря, повторите первый запрос на 23.09.2026 и 24.09.2026: занятость меняет состав топ-3, а ответ указывает число занятых на дату.

### Повторяемые проверки

Из корня проекта (при использовании виртуального окружения сначала активируйте его):

```powershell
python -m pip install -r backend/requirements-dev.txt
python -m unittest discover -s backend/tests -v
node --test tests/frontend.test.cjs
```

Backend-тесты используют настоящий FastAPI и временную SQLite-базу из исходного CSV; рабочая база не меняется. Проверяются валидация, готовность каталога, три исхода, фильтры, границы бюджетных баллов, порядок карточек и конкретные объяснения. Frontend-тесты проверяют формируемую разметку, контракт API, ошибки и таймауты в Node; визуальную проверку браузера они не заменяют.

| Астана / Флорист | 14.11.2026 | Не заданы | 1 карточка; в категории один профиль |
