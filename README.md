# hack-9923a583-ctrl-c
Hackathon team repository for ctrl+C

## Backend: каталог подрядчиков

Первый этап бэкенда использует SQLite. Схема хранит профили в `vendors`, а списки категорий, форматов, языков и занятых дат — в JSON-столбцах.

Когда Python 3.10+ установлен, из корня проекта создайте и заполните локальную базу:

```powershell
python backend/import_dataset.py
```

По умолчанию скрипт читает `hackathon dataset anonymized .csv` в корне проекта и создаёт `backend/data/vendors.sqlite3`. Повторный импорт обновляет профили с теми же ID. Путь к CSV или базе можно переопределить флагами `--csv` и `--db`.

### API подбора

Установите зависимости и запустите сервер из корня проекта:

```powershell
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.main:app --reload
```

Фронтенд отправляет `POST http://localhost:8000/api/recommend` (также доступен `/api/recommendations`):

```json
{
  "city": "Алматы",
  "date": "2026-11-14",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget": 1000000,
  "duration": 5,
  "language": "русский"
}
```

В `backend/matching.py` город, категория и незанятая дата — обязательные условия, по одному баллу за совпадение. Бюджет даёт 10 баллов, если цена не выше бюджета; цена ниже бюджета дополнительных преимуществ не даёт. За каждые 10% превышения бюджета снимается 1 балл (до −10). Длительность даёт до 10 баллов: если лимит меньше запроса, отнимается 2.5 балла за каждый недостающий час; формат и выбранный язык дают +3 за совпадение и −1 за несовпадение. Сортировка — по сумме баллов, затем по ID; наружу выдаются максимум три карточки. В карточке видна разбивка баллов и объяснение каждого совпадения. `backend/recommender.py` формирует статусы и объяснения пустых результатов. Ответ соответствует фронтенду: `status` (`success`, `category_not_found` или `no_matches`) и карточки в `results`. `GET /api/health` — проверка доступности сервера.
